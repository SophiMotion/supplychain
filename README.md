# 供应商库 · Supplychain

用于浏览、搜索和筛选机器人及相关产业供应商的静态 Web 页面。支持公司简介、产品、分类标签、图片、官网、新闻、专利和资料来源查看，适配桌面和手机浏览器。

- 仓库：<https://github.com/SophiMotion/supplychain>
- 网站发布地址：<https://sophimotion.github.io/supplychain/>

本仓库是独立的静态发布版，不依赖原云站点的登录、所有者权限或数据库服务。**没有 DeepSeek 调用、联网调研、自动新增企业或在线修改数据库功能**；搜索只查询本仓库收录的数据。

## 使用方法

1. 打开网站，在顶部输入关键词，然后点击“搜索”或按回车。
2. 点击左侧主营分类缩小范围；点击“全部供应商”恢复全部分类。
3. 点击企业行，查看右侧详情；手机端会打开详情面板，可使用关闭按钮或 `Esc` 退出。
4. 点击官网、新闻、专利或资料来源链接，在新标签页查看原始网页。
5. 搜索不到时，试用公司简称、产品名或更短的关键词，并清除现有分类；手机端还需检查“仅有视频”等筛选条件。

### 搜索逻辑

搜索是**不区分英文字母大小写的文本包含匹配**，不是语义问答、搜索引擎或模糊纠错。

| 输入示例 | 含义 |
| --- | --- |
| `减速器` | 查找检索文本中包含“减速器”的供应商 |
| `无框 电机` | 两个词必须都命中，但可以出现在不同字段、任意顺序 |
| `RV` | 与 `rv` 的查询效果相同 |
| 留空后搜索 | 清除关键词条件；已选分类等其他条件仍然生效 |

空格分隔的多个关键词按“并且”组合，再与主分类和视频条件取交集。不支持 `OR`、`*`、正则表达式、引号短语语法或拼音搜索。中文词语不会自动分词；例如连续输入 `无框电机` 会匹配这段连续文字，输入 `无框 电机` 则分别匹配两个片段。

当前数据使用预先生成的 `searchText`，覆盖已有的企业名称、别名、简介、产品、技术、应用、分类标签、展位、展馆、大会名称、官网地址以及新闻和专利的部分字段。**只有已收录进检索文本的内容才能被搜到**，不会实时抓取官网，也不会自动补充未收录的同义词。

左侧分类按企业的 `primaryCategory` 筛选，不按所有标签筛选；分类数量是整个快照的数量，不随关键词实时变化。标签用于展示，同一企业可以有多个标签。

桌面版显示左侧分类和顶部搜索；“仅有视频”和筛选栏“重置”仅在手机布局中显示。左下角“重置分类筛选”只重置分类；手机筛选栏“重置”或无结果提示中的“清除全部筛选”会重置全部查询条件。

## 本地开发与预览

开发环境需要 Git、Node.js **22.13.0 或更新的兼容版本**及 npm；推荐 Node.js 24 LTS。普通访问者只需浏览器，不需要安装这些开发工具。

```bash
git clone https://github.com/SophiMotion/supplychain.git
cd supplychain
npm ci
npm run dev
```

在浏览器打开终端显示的本地地址。开发服务默认只绑定 `127.0.0.1`，不会自动向局域网或公网开放。停止服务时，在终端按 `Ctrl+C`。

### 常用命令

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动本地开发服务 |
| `npm start` | 同 `npm run dev` |
| `npm test` | 执行自动化测试 |
| `npm run build` | 生成 `dist/` 静态文件，默认相对资源路径 |
| `npm run preview` | 通过 HTTP 本地预览已构建的 `dist/` |
| `npm run check` | 执行测试并构建 |
| `npm run test:e2e` | 按 `/supplychain/` 子路径构建并运行浏览器端测试 |

构建并预览：

```bash
npm run build
npm run preview
```

本项目通过 HTTP 请求读取 JSON。**请不要直接双击仓库根目录或 `dist/` 中的 `index.html`**，浏览器的 `file://` 安全限制可能阻止数据加载。

### 浏览器端测试

默认测试浏览器为 Playwright 管理的 Chromium。首次运行前先安装浏览器，后续可直接执行测试：

```bash
npx playwright install chromium
npm run test:e2e
```

Windows 用户若希望将浏览器下载到 D 盘，可以先在同一个 PowerShell 窗口设置以下环境变量，再运行安装和测试命令。路径仅为示例，可改成自己选定的目录；安装工具会向该位置写入浏览器文件，之后运行测试也需使用同一路径。

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = 'D:\playwright-browsers'
npx playwright install chromium
npm run test:e2e
```

如果本机已经安装 Google Chrome，也可以选择使用系统 Chrome，不必下载 Chromium。Windows PowerShell 示例：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
```

以上浏览器方案选择一种即可；`PLAYWRIGHT_CHANNEL` 未设置时使用默认 Chromium。测试会构建 `/supplychain/` 版本并自动启动本地预览，覆盖桌面和手机视口。手机视口模拟不等于已在真实 iPhone、Safari 或所有设备上验证。

### 与“双击离线版”的区别

- GitHub 的 **Code → Download ZIP** 下载的是本仓库源码，不是可直接双击运行的离线包。
- 源码安装依赖、构建后，可通过本地 HTTP 服务浏览；资料和图片在本地，外部官网、新闻、专利、视频链接仍需联网。
- 之前单独制作的“供应商库-离线网页版”及其轻量 ZIP 是另一种交付物，不能把源码 ZIP 与该离线包混为一谈。本仓库不包含那份大型压缩包。
- GitHub Pages 是在线托管网站，不是离线包，也不会让某一位访问者的电脑承担公开服务器。

## 部署到 GitHub Pages

本仓库包含 `.github/workflows/pages.yml`。工作流在推送 `main` 时运行，也可从 Actions 手动触发；它依次执行 `npm ci`、`npm test`、安装 Chromium 及其系统依赖、`npm run test:e2e`，测试通过后发布该次构建的 `dist/`。浏览器测试步骤会自动完成 `/supplychain/` 子路径构建。

首次启用时：

1. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。如果没有设置权限，请联系仓库管理员。
2. 将审核后的代码推送到 `main`，或打开 **Actions → Deploy supplier library to Pages → Run workflow**。
3. 等待构建和部署两个作业成功，在部署记录中确认网站地址并实际打开检查。

Pages 构建使用：

```bash
npm run build -- --base=/supplychain/
```

`/supplychain/` 是仓库对应的项目站点子路径。不要直接把资源路径改成 `/assets/...` 或 `/data/...`，否则浏览器会到域名根目录寻找文件，可能出现空白页或数据、图片 404。更换仓库名称时，应一起调整部署工作流、浏览器测试和本文链接。

工作流使用 GitHub 提供的短期令牌发布，不需要在前端加入个人访问令牌或任何模型服务密钥。部署受仓库与组织的 Actions、Pages 和环境权限控制；工作流存在不代表网站已自动发布，必须以实际成功的部署记录和页面检查为准。

### 以后绑定公司域名

在公司确认域名和 DNS 管理权限后，再进行以下配置：

1. 在仓库 **Settings → Pages → Custom domain** 设置公司指定域名，并按 GitHub 提示完成域名验证。
2. 在域名服务商处按 GitHub Pages 对应的 DNS 说明配置记录；子域名通常指向 `sophimotion.github.io`，不能在 DNS 记录中填写 `/supplychain/` 路径。
3. 如公司域名直接以根路径提供此站点，将工作流的构建基路径改为 `/`，并更新相关测试、站点链接及所需域名文件。
4. 等待域名解析与证书就绪，再启用/确认 HTTPS，测试数据、图片、搜索与外链。

当前仓库没有替公司选择域名或更改 DNS。不要在未确认归属的情况下添加域名配置。自定义域名改变访问地址，不会给静态站点增加后端或自动入库功能。

## 数据维护与更新

### 公开数据结构

`public/data/exhibitors.json` 的顶层字段包括 `schemaVersion`、`generatedAt`、`counts`、`categories` 和 `exhibitors`。每家供应商有稳定的 `id`，以及以下主要内容：

- 基础信息：`name`、`aliases`、`summary`、`primaryCategory`、`tags`、`conferenceNames`。
- 产品与媒体：`products`、`technologies`、`applications`、`logo`、`images`、`videos`、`hasVideo`。
- 原始来源：`officialWebsite`、`news`、`patents`、`sources`、`reviewNotes`。
- 检索与时间：`searchText`、`collectedAt`、`researchVerifiedAt`。

图片 `url` 应采用 `assets/light-image-...` 形式的相对路径，对应 `public/assets/` 中的实际文件；外部来源使用经过核对的 `https://` 或 `http://` 链接。请勿写入开发电脑的盘符路径、`localhost`、临时下载链接或授权参数。

### 推荐更新流程

1. 在本地创建工作分支，保存待更新信息的原始来源及采集时间，先核对企业身份，避免同名企业、经销商和品牌主体混淆。
2. 修改数据快照；保持 `id` 唯一，保留来源和待复核说明。不知道的字段保持缺失，不凭猜测填充。
3. 新增图片时先确认来源与使用权限，压缩为常见浏览器格式，放入 `public/assets/`，并更新对应相对路径。不要只修改扩展名来“转换”图片。
4. 同步重建受影响企业的 `searchText`，将文本转换为小写；更新 `counts`、`generatedAt` 和 README 中的版本统计。仅修改显示字段而不更新 `searchText`，会导致新增信息无法被搜索到。
5. 如变更数据规模，同步调整基于快照数量的测试预期；执行 `npm run check` 和 `npm run test:e2e`，实际检查公司搜索、分类、无结果状态、图片、外链和手机详情。
6. 提交并审核差异后合并或推送到 `main`，等待新的 Pages 部署成功，再确认在线数据版本。

`src/data/normalize.js` 保留了已有数据标准化逻辑供维护参考，但本仓库没有提供原云端采集系统或常驻自动导入后台。直接手工更新 JSON 时，应遵守当前公开数据结构与校验规则。

### 从已有轻量离线包导入（可选）

`scripts/import_snapshot.py` 用于导入**可信的、符合已有轻量离线包格式的 ZIP**。该维护工具额外需要 Python 3；日常访问网站、Node.js 开发、构建和 Pages 部署均不需要 Python。

**导入会替换 `public/data/exhibitors.json`，并覆盖 `public/assets/` 下同名图片。请先创建工作分支或备份现有公开数据，确认 ZIP 和目标仓库后再执行。** 从仓库根目录运行：

```bash
python scripts/import_snapshot.py "轻量离线包的完整路径.zip"
```

macOS 等使用 `python3` 命令的环境可相应替换解释器名称。脚本读取 ZIP 中 `index.html` 的 `offline-catalog` 数据，去除每家企业的 `contacts` 字段，检查企业 ID 和媒体路径，只导入被引用的轻量媒体及 JSON；它**不会修改原 ZIP**，也不会删除目标目录中已有的其他图片。

该脚本不是通用网站下载器，也不能导入任意压缩包。路径和大小检查不代表资料已完成事实、版权或完整隐私审查。导入后仍需检查数据差异、统计、搜索文本、来源与媒体格式，按上面的更新流程修改测试预期及 README，并完成测试后再发布。

### 回滚

如果发布后发现问题，先定位造成问题的提交，使用 `git revert <提交号>` 创建撤销提交，再推送到 `main` 触发重新部署。不要使用强制推送来覆盖共享历史。涉及数据纠错时，同时记录错误字段和更正依据；部署回滚不会让已经被他人下载的数据副本消失。

## 安全、隐私与版权

- 此仓库及 Pages 网站公开可访问。`public/` 下的所有文件都可能被任何访问者下载；前端隐藏字段不等于保密。
- 发布数据已去除原始 `contacts` 字段，因为这些字段未在页面展示，且缺少逐项可追溯来源。后续新增数据也不应默认公开个人联系方式、内部采购信息、账号标识或未经授权的材料。
- 不提交 `.env`、API Key、访问令牌、云端所有者配置、数据库凭据或个人浏览器状态。静态站点不需要这些信息。
- 企业名称、商标、Logo、产品图片和来源网页内容的权利归相应权利人所有。保留来源链接不代表已经取得再发布授权；采购使用和对外公开仍需按公司的合规要求确认。
- 本仓库不因公开展示就授予第三方资料的使用许可，也不在未授权情况下额外授予源代码开源许可证。依赖软件遵循各自许可证。
- 若发现信息错误、失效链接或涉及权利问题，请通过仓库 Issue 联系维护者，提供企业名称、具体字段及可核对的公开来源；不要在公开 Issue 中粘贴密钥或私人联系方式。

## 常见问题

**网页打不开或提示数据加载失败？** 先确认访问的是已完成部署的 Pages 地址，或者通过 `npm run dev` / `npm run preview` 启动的本地 HTTP 地址，而不是直接双击 HTML。首次访问需要下载资料快照，较慢的网络可能会在“正在载入供应商资料”停留一段时间；图片也会按需加载。若长时间不完成，检查网络、部署是否成功、`data/exhibitors.json` 是否可访问，以及基路径是否仍为当前站点配置。

**搜索不到企业，就会自动联网查找吗？** 不会。此版本是只读静态快照，未收录企业需要维护者核实资料、更新文件并重新发布。

**为什么数字不是云端显示的 1,237 家？** 当前发布数据来自上述 1,236 家的本地快照，不包含后来只保存在原云端的新增记录。需要先取得、核对并导入那部分记录，不能仅修改显示数字。

**网页写“最近 3 年新闻”，内容会每天自动刷新吗？** 不会。新闻条目来自数据生成时的筛选结果，静态页面不重新抓取或滚动更新；维护者应定期更新快照。

**图片占位或官网待核验是否表示页面坏了？** 不一定。缺少原图、不支持的源文件格式、没有官网记录或失效外链均可能造成这种显示，应检查原始资料；不要用占位地址冒充已核验官网。

**老板使用 MacBook 可以访问吗？** 可以使用现代浏览器访问 Pages 网站；本地开发同样可在 macOS 安装 Node.js 后运行。若要求完全不安装软件、双击打开，应另行使用已制作的独立离线 ZIP，而不是仓库源码包。
